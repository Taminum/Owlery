# Ember — производство графики и анимации

Статус: производственный план и пробный пакет; полный выпуск ждёт оценки пробы владельцем.

## Зафиксированная модель

Взрослая Ember в чиби-пропорциях из нижнего ряда эталона: длинные растрёпанные медно-рыжие волосы, петля-ахоге, янтарные глаза, чёрная кошачья заколка с розовой мордочкой справа для зрителя, дополнительные заколки, огромная чёрная худи с розовыми деталями и розовым котиком. Чёрные чулки с розовыми полосами у верхнего края, маленькая чёрная обувь. Пропорции большого портрета не переносить на маленького маскота. Не зеркалить готовые кадры: заколка и детали асимметричны.

Сохранить характер: ворчит, краснеет, скрывает радость, говорит «бака». Текст и служебные значки поставлять отдельно от рисунка. Panty Storm — комедийные отдельные предметы из-за спины; одежда самой Ember не снимается и не меняется.

## Производственный процесс

1. **Проба до тиражирования.** Встроенный imagegen, исходный концепт передаётся как reference. Одна серия согласованных кадров: сидение/дыхание, моргание, annoyed, замах/бросок. Не обещать идентичность между генерациями: проверять её визуально.
2. **Подготовка пробы.** Проверить реальную альфу, сетку, одинаковый масштаб и точку контакта с краем. Нарезать без дорисовки и перегенерации, сохранить все исходные кадры. Сначала исправлять исходник, если плывёт лицо/рисунок, а не скрывать проблему ресайзом.
3. **Анимационная проба.** Воспроизвести последовательности с явным таймингом; дыхание не заменяет blink, а покачивание всей картинки не считается новой актёрской анимацией. Бросок имеет подготовку, замах, release, follow-through и возвращение. Предмет получает отдельную дугу, вращение, приземление и затухание.
4. **Контрольная точка из раздела 14 ТЗ.** Владелец оценивает внешность и движение пилота. До этой оценки не запускать массовое производство финального набора.
5. **Полный выпуск.** После принятия пилота фиксировать базовую модель и палитру, делать небольшие серии с одним эталоном. Если серии дают неприемлемый дрейф — выделить части и делать cutout-анимацию с отдельными глазами/ртом/волосами/рукавами; не объявлять плоский PNG готовым ригом.
6. **Упаковка и приёмка.** Отдельные PNG, атласы, JSON с кадрами/таймингом/якорями, анимированные WebP, автономная HTML-галерея. Проверить на светлом/тёмном/шахматном фоне и при размере 160/220/320 CSS px; передать Claude только пакет с отмеченным статусом.

## План полного набора

Числа кадров ниже — целевые объёмы, не утверждение о готовности. Удержания задаются длительностью, а не дубликатами PNG. Idle и blink — отдельные клипы с общей базовой позой.

| ID | Актёрское действие | Цель по кадрам / времени | Повтор |
|---|---|---|---|
| idle | сидит на краю, дышит, волосы и рукава догоняют движение | 8–12 / 2.4 s | цикл |
| blink | открыты → полузакрыты → закрыты → открыты | 4–5 / 0.18–0.26 s | один, интервалы 3–7 s |
| happy | сначала сдерживает улыбку, затем радуется | 8–12 / 1.2 s | один → idle |
| blush | отводит взгляд, нарастает румянец, прячется в ворот | 8–12 / 1.6 s | один → idle |
| annoyed | хмурится, надувает щёки, сжимает рукав | 8–12 / 1.2 s | один → idle |
| angry | сердитый взмах рукавом, отыгрыш ахоге и волос | 10–14 / 1.2 s | один → idle |
| sleepy | тяжелеют веки, кивок, зевок | 10–14 / 2 s | один → sleep |
| sleep | спит на фиолетовой подушке, дыхание, волосы | 8–12 / 3.2 s | цикл |
| wake | просыпается, собирает волосы, садится | 10–14 / 1.5 s | один → idle |
| alert | замечает проблему, выпрямляется, указывает | 8–12 / 1 s | один → спокойное alert hold |
| panic | комедийная суета с ключом, без перекрытия алерта | 12–16 / 1.2 s | ограниченный цикл |
| celebrate | взмах обоих рукавов, короткий подскок, мягкая посадка | 12–16 / 1.6 s | один → idle |
| smug | самодовольная улыбка, прищур, короткий кивок | 8–10 / 1.2 s | один → idle |
| concerned | напряжённый взгляд и наклон вперёд | 8–10 / 1.2 s | один → idle |

Сон имеет собственную базовую позу; обязательны переходы seat→sleep и sleep→seat. Паника и storm не заменяют официальную индикацию неисправности. Критический алерт прерывает шутку.

## Форматы и контракт для Claude

- Исходные генерированные листы PNG RGBA сохранять неизменёнными вместе с промптом и SHA-256 эталона.
- Мастер-кадры: PNG RGBA, целевой холст 512×512, sRGB, прямой alpha. В пилоте сохранять фактическое разрешение генератора и указывать его в JSON; не выдавать апскейл за новые детали.
- Кадр не обрезать независимо от соседей. Общий pivot сидячего набора — точка контакта с краем, не низ ботинок; для сна отдельный pivot и прописанный переход. После проверки сетки записать фактические координаты.
- Атласы: PNG + JSON, страницы не больше 2048×2048; 2 px padding/extrusion для texture-сэмплинга при окончательной упаковке. Пилот с CSS-выборкой целой ячейки может обходиться без extrusion, явно указать это в manifest.
- JSON: версия схемы, статус пакета, ссылка на эталон, размеры, clips с последовательностью frame IDs, длительностями в миллисекундах, loop, pivot, release markers, reduced-motion poster. Все ссылки относительные, без вшитого base64.
- Animated WebP с alpha — просмотровая копия клипов; не единственный источник и не обязательная зависимость runtime. GIF не основной формат: ограничены полупрозрачные края.
- Для runtime предпочтительны отдельные PNG/атлас и существующий фронтенд; CSS/WAAPI для частиц. Это предложение к интеграции, не изменение архитектуры. Rive/Lottie не выбирать без настоящих исходников/рига.
- Отдельные props: голубые/белые полосатые трусики с розовым бантом из эталона, розовый вариант только после сверки; ключ, ноутбук, подушка. Для частиц допустим rotation одного предмета, деформация ткани требует отдельных рисунков.
- Реплики — UTF-8 JSON, русские строки вне графики. Sound v2; аудио сейчас не требуется.

## Panty Storm: тайминг и слои

Слои: задние волосы → тело/одежда → рука/предмет → передние волосы → мимика → отдельный слой частиц UI.
0–300 ms: замечает поддразнивание; 300–650 ms: достаёт предмет; 650–1500 ms: серия бросков с release markers; 1500–2400 ms: краснеет и возмущается; 2400–3200 ms: возвращается в idle.
Частицы живут 3–6 s от своего release: дуга с ускорением вниз, вращение, короткое приземление, fade-out. Случайность ограничена нижней зоной интерфейса. У всех частиц pointer-events:none, фиксированные координаты overlay, нулевой layout shift. При выключении/смене страницы/критическом алерте немедленная очистка. Reduced motion: один неподвижный blush poster и реплика, без летящих предметов.

## Проверки и честный статус

Автоматически: присутствие alpha и нулевой alpha вне персонажа; непустые кадры; одинаковые размеры; отсутствие касания границ ячейки; frame IDs/тайминги/пивоты; несколько реально различных кадров; для WebP количество кадров >1 и разные пиксели; относительные существующие ссылки; hashes исходников.

Визуально: та же Ember и сторона заколки; постоянные пропорции/размер лица/детали худи; нет мерцания текстур и прыгающего места посадки; закрытые глаза действительно закрыты; шов цикла; контакт с краем интерфейса; бросок совпадает с release предмета; альфа на контрастных фонах; читаемость на малом размере. Автоматические проверки не доказывают художественную приёмку.

Пакет помечать `pilot-unapproved`, `needs-rework` или `approved` только с фактическим основанием. Подготовленный план, контактный лист и отдельные иллюстрации не считать завершённым анимированным комплектом. В handoff перечислить существующие клипы и отсутствующие действия; ничего не подключать к production автоматически.

## Результат первой пробы, 2026-10-16

`assets/ember/pilot-v1/` содержит 16 PNG RGBA, атлас, manifest, исходные генерации/промпты, четыре действительно многокадровых WebP и автономную от основного приложения галерею. Статус **needs-rework**, художественной приёмки нет. Canvas кадра 512×512, рисунок около 300 px высотой без апскейла. WebP декодированы обратно: idle — 4 кадра / 3 уникальных, blink — 5 / 4, annoyed — 6 / 4, throw — 5 / 5. У всех есть alpha; все PNG непустые и не касаются края своего упакованного холста.

Наблюдение: две попытки генерации листа сохранили общий образ, но не дали точную сетку и постоянные детали. Промпт с координатами не является гарантией регистрации. При упаковке потребовались силуэтные bounding boxes и проверенные опорные точки. Возврат после броска резкий, отдельный предмет имеет ореол; это кандидаты, не финальные ресурсы. Для дальнейшего выпуска предпочтительна единая мастер-поза с настоящими прозрачными слоями и сменной мимикой, а новые рисунки целого тела — только для крупных действий (сон, бросок, паника, посадка). Послойного мастера пока нет; плоский лист не выдаётся за риг.

В браузере проверены запуск броска и реальный отдельный предмет после release, пауза в момент полёта, фоны тёмный/светлый/шахматный, три частицы и их удаление при переходе в idle, ручное reduced motion (0 частиц), отсутствие ошибок console. При viewport 390×844 ширина содержимого и clientWidth совпали (375 CSS px с полосой прокрутки), горизонтального overflow нет. Скриншоты сохранены в `previews/`. Эти проверки относятся к отдельной галерее, не к интеграции в RemnaScope. Автоматическая реакция на OS reduced motion и фоновые вкладки реализована в просмотрщике, но отдельного browser-теста этих двух событий пока не было.

Следующая контрольная точка: владелец оценивает образ, размер и характер движения пилота согласно разделу 14 ТЗ. Затем — послойный мастер/доработка контуров, повторная короткая проба и только после этого выпуск остальных состояний из таблицы.
