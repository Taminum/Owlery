# Remnawave API: что ещё можно читать (16.10.2026)

Источник: контракт `remnawave/backend`, `libs/contract/api/controllers/*.ts` (ветка main). Пути даны после `/api/`.
Сейчас Owlery читает только `nodes`, `users/` (страницами), `system/stats`, `system/metadata`, `bandwidth-stats/nodes`.
Поля ответов нужно сверять на живой панели (v3.4 в тестовых данных урезаны), поэтому всё ниже «кандидат», а не обещание.

## Только чтение, безопасно

| Что | Путь | Зачем нам |
|---|---|---|
| Трафик нод в реальном времени | `bandwidth-stats/nodes/realtime` | «Пульс сети»: живая скорость по каждой ноде без ожидания агентов |
| Расход нод за период | `bandwidth-stats/nodes`, `bandwidth-stats/nodes/usage` | уже частично есть; usage даёт ряд для графика |
| Кто сколько потратил на ноде | `bandwidth-stats/nodes/{uuid}/users`, `.../nodes/users` | топ пользователей по ноде |
| Расход одного пользователя | `bandwidth-stats/users/{userId}` | карточка пользователя |
| Расход по сквадам | `bandwidth-stats/internal-squads/{uuid}/usage` | отчёт по группам |
| Пользователи: лимит, срок, статус | `users` (поля `trafficLimitBytes`, `expireAt`, `status`, `userTraffic.*`, `onlineAt`) | предупреждения «заканчивается срок / трафик», дайджест |
| Куда ходит подписка | `users/{id}/subscription-request-history`, `subscription-request-history` | кто и с какого IP/клиента брал подписку |
| Доступные пользователю ноды | `users/{id}/accessible-nodes` | диагностика «почему не работает» |
| Метрики нод | `system/nodes/metrics`, `system/stats/nodes`, `system/stats/bandwidth` | нагрузка, онлайн |
| Сводки панели | `system/stats/recap`, `system/stats/digest` | готовые цифры для дайджеста |
| Биллинг инфраструктуры | `infra-billing/providers`, `.../nodes`, `.../history` | даты оплаты серверов: «через 3 дня платить за VPS» |
| Хосты, профили, сквады | `hosts`, `config-profiles`, `internal-squads`, `external-squads` | карта «что на что назначено» |
| Бесконечный список пользователей | `users/stream` | вместо страниц, если пользователей много |

## Меняют состояние (не трогаем без отдельного решения)

`users/{id}/actions/*` (включить, выключить, сбросить трафик, продлить, отозвать подписку), `bulk/*`,
`nodes/{uuid}/actions/*` (перезапуск, сброс трафика), `connections/*` (запускает задание на ноде и
`drop` обрывает соединения). Токен API у нас read-only, и это правильно оставить так.

## Что я бы взяла первым

1. **`bandwidth-stats/nodes/realtime`** для «Пульса сети»: дешёвый запрос, сразу даёт живую картину по всем нодам.
2. **`users` с `expireAt` и `trafficLimitBytes`**: тревога «у пользователя заканчивается срок или трафик» в Telegram и дайджест. Данные у нас уже приходят целыми страницами, нужно лишь сохранять два поля.
3. **`infra-billing`**: напоминания об оплате серверов, если ты ведёшь там даты (нужно проверить, заполнено ли у тебя).
4. **`subscription-request-history`**: «кто качает подписку» и поиск утёкших подписок (много разных IP на одну).

## Риски

- Поля ответов зависят от версии панели; у нас уже есть слой версий (`v3.go`), новые поля добавлять туда и ронять только свой кусок, а не весь синк.
- `users/` с большим числом строк уже читается страницами; `stream` пробовать только после проверки на живой панели.

## Обновление 13.11.2026

Что из «первых четырёх» уже сделано: `bandwidth-stats/nodes/realtime` (Пульс сети) и срок и лимит трафика пользователей (`expireAt`, `trafficLimitBytes`, тревоги и дайджест). Осталось два пункта из списка выше: `subscription-request-history` и `infra-billing`.

Релизы панели 3.4.4–3.4.10 (сентябрь–ноябрь): ломающих изменений нет. Новое в API: клон хоста, поле `includeInSrrRules` у хостов, переменные «дата следующего сброса трафика». Наш слой `v3.go` на 3.4.x остаётся рабочим.

Контроллеры, которых не было в списке выше:

| Что | Путь | Чтение или запись | Зачем нам |
|---|---|---|---|
| Устройства по HWID | `hwid/devices`, `hwid/devices/{userId}`, `hwid/devices/stats`, `hwid/devices/top-users` | чтение | сколько устройств на подписку, у кого больше всех: признак «подписку раздали». Работает, только если HWID включён на панелях |
| Отчёты торрент-блокера | `node-plugins/torrent-blocker`, `.../torrent-blocker/stats` | чтение | кто и на какой ноде качает торренты: тревога и строка в дайджесте. Требует включённого плагина на нодах |
| Плагины нод, списки, интеграции | `node-plugins/*`, `node-integrations/*` | запись | не трогаем |
| Очистка отчётов | `node-plugins/torrent-blocker/truncate` | запись, необратимо | не трогаем |

Пути без глаголов взяты из `routes.ts` и комментариев контракта: перед кодом сверить с живой панелью. Токен остаётся read-only.

Что я бы брала дальше, по пользе: подписки (`subscription-request-history`, поиск утёкших по числу разных IP), потом торрент-блокер, потом HWID. `infra-billing` не нужен, пока даты оплаты серверов ведутся в нашем разделе «Платежи».
