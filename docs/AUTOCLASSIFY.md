# AutoClassify: автоклассификация неизвестных сайтов (Gemini)

Статус: **этап A и этап B готовы** (клиент, пробный прогон, очередь, фоновая работа, автоприменение, метки). По умолчанию выключено: включает владелец. 

## Что уже есть

- Клиент Gemini API (`internal/gemini`): ключ читается из файла при каждом вызове, передаётся только в заголовке, не попадает в ошибки, логи, ответы API и интерфейс; ответы читаются с лимитом размера, редиректы не выполняются, названия моделей проверяются перед подстановкой в адрес; 429, 5xx, таймауты, обрыв по токенам и мусор в ответе различаются и не роняют работу.
- Подготовка и проверка (`internal/classify`): отправляются **только регистрируемые домены** (eTLD+1 по Public Suffix List). IP-адреса, `localhost`, внутренние имена (`.lan`, `.local`, `.internal`, `.arpa` и т.п.), одиночные метки, голые публичные суффиксы, поддомены и всё невалидное не отправляются и сохраняют прежний статус. Категория в ответе это **номер из списка существующих категорий**: модель не может создать категорию. Домен, о котором не спрашивали, дубликат, неизвестный номер, уверенность вне 0–1, мусор в тексте отбрасываются, строки ограничены по длине и очищены от управляющих символов. Название сервиса сохраняется только при уверенности не ниже 0,75.
- Пробный прогон (`internal/autoclassify`): 100 неизвестных доменов, из них 60 самых посещаемых и 40 случайных; пакеты по 10–20; повторяется только то, на что не пришёл корректный ответ; до 3 попыток на пакет, пауза по `Retry-After` или экспоненциальная с джиттером; отказ ключа останавливает прогон сразу. Ответы сохраняются **отдельно** (`classify_dryrun_items`), ничего не применяется, счётчики не меняются.
- Настройки владельца (Настройки → Автоклассификация): состояние ключа (есть/нет, сам ключ нигде не показывается), выбор модели из списка, который отдаёт сам провайдер, размер пакета, дневной лимит (пока для будущей фоновой работы), кнопка пробного прогона, таблица результатов с фильтрами и сводкой.

## Что отправляется провайдеру

Только названия неизвестных регистрируемых доменов (например `example.com`) и список ваших категорий. Не отправляются: IP, устройства, пользователи, время и число соединений, пути ссылок, токены, любая статистика трафика. Поддомены тоже не отправляются.

## Как задать ключ и запустить пробный прогон

1. Ключ Gemini API получите в Google AI Studio. Положите его на сервер в файл (в интерфейс ключ не вводится):

   ```powershell
   $k = Read-Host "Gemini API key"; $k | ssh scope-host 'umask 077; cat > /opt/remnascope/secrets/gemini_api_key; chown 65532:65532 /opt/remnascope/secrets/gemini_api_key; chmod 400 /opt/remnascope/secrets/gemini_api_key'
   ```

   Перезапуск не нужен: файл читается при каждом обращении.
2. Откройте **Настройки → Автоклассификация**: статус ключа станет «есть на сервере», в списке появятся доступные модели. Выберите модель (подойдёт экономичная Flash), нажмите «Сохранить».
3. Нажмите **«Запустить прогон»**. Он идёт в фоне 1–2 минуты. Результат: доля корректных ответов, предположения (уверенность ниже 0,6), «не определено», ответы без результата, распределение по категориям, расход токенов и запросов.
4. Сверьте 20–30 строк вручную (особенно «предположения» и спорные) и скажите, что поправить в категориях или инструкции модели.

Убрать ключ: `ssh scope-host ': > /opt/remnascope/secrets/gemini_api_key'`. После этого запросы к провайдеру прекращаются сразу, собранные классификации не теряются.

## Конфигурация и данные

- Переменная `GEMINI_API_KEY_FILE` (в `compose.prod.yml` задана как `/run/secrets/gemini_api_key`). Файл секрета создаётся пустым при деплое (`ship.sh`), пока владелец не положит ключ.
- Миграция `0012_autoclassify.sql`: `autoclassify_settings` (одна строка, `enabled` по умолчанию выключен), `classify_dryrun_runs`, `classify_dryrun_items`. Старые правила и категории не затрагиваются.
- Откат: миграция только добавляет таблицы; откат релиза возвращает предыдущие образы, таблицы можно оставить (они не используются старой версией).

## Доступ

Только владелец. Все пять эндпоинтов (`/api/v1/autoclassify`, `/models`, `/settings`, `/dryrun` GET и POST) возвращают 403 остальным ролям, 401 без входа; ответы не содержат ключа (проверяется тестом). Изменение настроек и запуск пишутся в аудит без секретов.

## Автоматическая работа (этап B)

- **Включение:** Настройки → Автоклассификация → «Автоматическая работа». Нужны ключ на сервере и выбранная модель; включение требует галочки «я понимаю, что названия неизвестных сайтов уходят провайдеру». Выключатель действует сразу, собранные категории остаются, приём событий не затрагивается.
- **Как работает:** раз в 5 минут обработчик находит неизвестные сайты за последние двое суток и ставит их в очередь (`classify_jobs`, один домен: одна запись). Берёт пачки по 10–20 с `FOR UPDATE SKIP LOCKED` (безопасно для нескольких копий), самые посещаемые первыми. IP, localhost, внутренние имена и сайты с готовым правилом в очередь не идут или помечаются «пропущено».
- **Где хранится результат:** обычное правило в `service_rules` с `source='auto'`, `rule_version=0` (самая низкая версия), плюс уверенность, модель, основание и время. Ручное правило (1000) и встроенное (1) для того же адреса всегда сильнее; удалите ручное, и вернётся автоматическое. События и счётчики не переписываются.
- **Метки:** «правило», «вручную», «авто», «предположение» (уверенность ниже 0,6) в списках «Сайты» и «Назначения»; в панели сайта видны модель, уверенность и дата.
- **Лимиты и сбои:** дневной бюджет в сайтах (поле «Лимит сайтов в сутки», 0 = пауза). 429: пауза по `Retry-After` или экспоненциально с джиттером до 15 минут, попытка не списывается. 5xx, сеть, битый ответ: повтор с задержкой, после 5 попыток запись «ошибка» и новая попытка через сутки. Отказ ключа: пауза 10 минут, статус «ключ не принят». Неполный ответ: повторно спрашиваются только недостающие. «Не определено»: повторный вопрос через неделю.
- **Пересмотр:** автоматические результаты старше 30 дней раз в час по 50 штук возвращаются в очередь; ручные никогда.
- **История:** кнопка «Разобрать историю» один раз ставит в очередь старые неизвестные сайты кусками по 300; дальше их обрабатывает дневной лимит, перезапуск ничего не теряет.
- **Миграция:** `0014_autoclassify_queue.sql` (добавляет таблицы `classify_jobs`, `classify_budget`, столбцы в `service_rules` и `autoclassify_settings`, разрешает `source='auto'`).
- **Проверить состояние:** карточка «Автоматическая работа» (очередь, определено, расход за сутки, ошибки, последний успешный ответ).
- **Откат:** выключить в интерфейсе. Убрать все автоматические правила: `DELETE FROM service_rules WHERE source='auto';` (сайты вернутся в «Не определена»). Откат релиза возвращает прежние образы, таблицы можно оставить.
